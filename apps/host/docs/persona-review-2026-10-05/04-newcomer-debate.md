# Round 2 — reviewer 04: newcomer from TikTok

I read all eight original reports and the complete shared ballot independently. I did not consult peer votes or debate documents. This remains a simulated perspective of a first-time visitor curious to try Strata; gender supplies no assumptions about competence or preference. No observed usability findings, app changes, browser launch or model execution are claimed.

## Specific challenges

1. **01-gamer G02 and 05-tinkerer proposal 2 — retaining two visible Beginner dials.** Both reviewers value precise tuning and shorten the hints. Shortening prose alone still leaves Prompt batch as an apparently necessary first choice. From this newcomer perspective, Automatic is sufficient until a specific need arises. I vote **B02 CONTEXT** and preserve a visible Custom summary, exact-entry alternatives and Expert access. This challenges the default hierarchy, not the availability of the control.

2. **02-mac M02, 03-teacher T03 and 07-research proposal 2 — keeping both rates and the sample selector visible in default Engine feedback.** Smaller type and a nearby Demo badge help, but a first-time visitor still has to interpret reading versus answer throughput and token samples before deciding whether settings fit. The memory decision is more immediately useful. I vote **B03 MEMORY** and **B08 FIT**. Deliberate comparison retains both rates; Speed details remains discoverable with its evidence status.

3. **05-tinkerer proposals 10 and 12 — adding cache/placement/threads to initial setup review and Ready.** These facts belong in execution/loaded-setup details. A first chat should require understanding the exact selected model, actual download amount and fit, without extra parameter vocabulary. Scope or a meaningful custom-state warning can stay visible. I vote **B14 YES** and **B16 YES**, whose compact defaults preserve technical access.

4. **03-teacher T06 — “Show other file formats (quantizations)”.** Quantizations are exact model variants, and that label could be read as accepted document or file-format support. “Show other variants” is a better default label with quantization explained in Details. I support **B07 YES** and **B20 YES**; neither implies supported input formats.

## Concessions and changed positions

**Expert recommendations should remain visible.** My N03 moved recommended values to field Details. **05-tinkerer proposal 3, 01-gamer G04 and 07-research proposal 3** make a useful opposing point: Expert is already an intentional detailed editor, and a recommended value supports a quick comparison and safe recovery. I change this part of N03 and vote **B05 YES**, retaining recommendation, application timing, errors and per-field revert while collapsing general effects.

**One selected recommendation is clearer than unique-winner cards.** N05 proposed a shared card with profile tabs and N04 retained compact cards. **02-mac M05** clarifies a stronger consistent structure: choose the priority, inspect one result, then act. I adopt **B06 SELECTOR** instead of making the number and arrangement of cards depend on current winners. A concise shared-winner note still explains identical results, and no-fit recovery stays visible.

**Capability status deserves a concise visible line.** N04 focused on fit/download and one relevant caveat. **08-office #5 and 07-research proposal 4** persuaded me to prefer **B19 VISIBLE** using actual metadata. This replaces generic prose; it does not add a list of hypothetical workplace or research warnings. A default recommendation must not read as proof of task quality.

**Four core steps are sufficient when review remains explicit.** Round 1 covered and preserved the existing five-step path. The ballot's OPTIONAL alternative retains the hardware/model decisions, commitment review, preparation, readiness and resume behavior while making Tune expandable. I now vote **B12 OPTIONAL** because tuning need not be a separate required stop. No peer report established a tested advantage for changing the step count; this is my design judgment about the exact ballot wording. It requires resume mapping and visible download/configuration review, not bypassing review.

My top three are **B08 FIT**, **B13 RENAME**, and **B14 YES**: compact decision facts, understandable choices and a concrete download review before preparation.
