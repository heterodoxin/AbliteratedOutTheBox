Round 1 independent review. No other persona reports consulted. Review only; no model, server or browser execution, source edits or delegation. ## Goals and evidence

Simulated persona goals: get a stable setup for chat, revising prose, translation, spreadsheets and contracts; understand document capacity; choose with little jargon; avoid repeatedly tuning before ordinary work. This is a simulated judgment, not a usability test or observed user behavior.

Observed: Engine Beginner gives Context and Prompt batch equal visual weight, followed by a large speed/memory panel and six savebar controls (01; Tuning.tsx). Expert retains searchable parameters, Raw config and a shared draft. Models has three tall recommendation cards; Balanced and Performance show the same exact model and repeated facts while Agentic has no approved fit (07). Comparison repeats three complete preview cards, including unavailable start-answer timing (08). Profile onboarding repeats profile purpose in the choice tiles and recommendation (09).

Observed source: `Document` means a 4,096-input-token timing sample with 256 output tokens; it does not describe accepted file formats. Recommendations use memory fit, catalog review/order and compatible speed evidence; no spreadsheet or contract evaluation is established by those inputs. Setup defaults to Balanced, preserves choices, offers optional tuning, separates preparation stages and permits Chat only after loading. Demo operations are explicitly simulated; native engine integration and production evidence remain deferred.

Simulated friction: “Agentic,” “quantization,” token rates and batch tuning require interpretation before I can answer “Will this help me revise this document?” The demo label is valuable but its placement does not stop the very large rates from feeling like a recommendation quality score. Nothing here establishes XLSX handling, tool safety, legal reliability or confidentiality. My proposals must not invent those guarantees.

## Three must-do votes

1. **#5 — visible task-review evidence and plain profile labels.** Speed and model name cannot answer my workplace capability question.
2. **#8 — concise comparison rows.** Comparing three repeated panels makes the decision harder than it needs to be.
3. **#10 — model-first onboarding choice.** Keep a sensible default and exact model, remove duplicate purpose text, preserve access to evidence.

## Two opposed changes

1. **Oppose deleting Demo / provisional / fit-unknown states to shorten the UI.** These are decision facts. Keep compact, visible labels; move explanatory paragraphs into details. Production curation and native execution remain pending.
2. **Oppose “Office-ready,” “Spreadsheet model,” “Safe for contracts,” or “Private” badges derived from speed, fit or profile.** Those claims need separate task/integration evidence. Use the existing review metadata and explicit unknowns; this review does not request an enterprise features expansion.

## Round 1 conclusion

Keep the shared draft, exact variants, loading consequences, fit checks and resumable five-step flow. Reduce default content around the decision to one model, one fit summary and one task-evidence cue. My preference is compact default screens with optional technical depth, not removal of information required to distinguish simulation from a working native engine.
